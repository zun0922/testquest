> **Cowork が全部を読み切れない場合**は、★印の2件＋本パッケージ＋画像3枚（計6点）に絞って再添付してください。
> 8枚を書くのに必要な情報はその6点で足ります（不足分は本ファイルの「📦 プロジェクトコンテキスト要約」が補います）。

**zip は gitignore 対象（再生成可能）。** 作り直す場合：


### 主題の根拠：既存を壊さない設計（4枚目の素材）

**シナリオJSON 71本は Phase 2 を通じて一度も変更していない。**

- 音声は**パスの規約**で解決（`{シナリオID}/{ノードID}.m4a`）。データに参照を書かない
- エンディング・編成は**別ファイル**（`endings.json`・`casting.json`）に差分だけを持つ
- ヒントは既存データへ**追記のみ**（本文は不変・削除0行）

結果、**監修済みの学習コンテンツに触れずに機能を6件足せた**。

### 品質の仕組み（5枚目の素材）

機能ごとに「**コードとデータの食い違い**」を CI で落とす検査を足した。

| 対象 | 見張っていること |
|------|----------------|
| 音声 | 全ノードに音声があるか／余分なファイルが残っていないか |
| ヒント | 強調語が**本文に実在するか** |
| エンディング | 判定に使う理論値が**シナリオデータと一致するか**（データを直すとCIが落ちる） |
| 編成 | 差し替え後に**旧キャラの名前が残っていないか** |
| 画面レイアウト | **最長の設問**でも文字が隠れないか |

### 人が触って分かったこと（6枚目の素材・本フェーズの学び）

自動テスト53件とは別に、**人が実機で確認する項目を7件だけ**定義して実施した（PO が iPhone で実施・PASS 7／失敗0）。
自動と同じことを人手で繰り返さず、**機械に判定させられない観点だけ**に絞ったのが要点。

その7件から、**自動テストでは絶対に拾えない指摘が2件**出た。

| 指摘 | なぜ自動では拾えないか |
|------|---------------------|
| 早送りの速度が「速すぎる／遅すぎる」 | 進む・止まるは機械で検証できるが、**速さが人に合うか**は判定できない |
| 女性キャラの口調が声に合わない | 文字だけのレビューでは通った。**声とセットで聴いて初めて**分かった |

### 正直な限界と反省（7枚目の素材）

**やり残していること**

- **102項目の手動テストは未実施**（Phase 1 からの継続課題）。自動テスト53件・全数監修・本番での実機確認で代替中
- 法務確認は外部の結果待ち（社内利用の範囲で運用中）

**プロセス上の反省4件**（「何が起きたか → どう直したか → 次にどうするか」で構成する）

| 何が起きたか | どう直したか |
|------------|------------|
| **合格基準を後から作った**（機能が本番稼働してから定義した） | 基準を新設し承認。次フェーズは**実装前に置く** |
| **文書が3週間、実態と正反対のまま残った**（「未実装」と書かれたまま本番稼働していた） | 4文書を整合させ一括承認。**機能を出すときに文書も同時に動かす**ルールを明文化 |
| **修正が別の不具合を生んだ**（ボタンを押せるようにしたら、ヒント文が隠れた） | 画面の重なりを**実寸で検査するテスト**を追加 |
| **直し過ぎた**（速すぎた早送りを、今度は手動より遅くした） | **人が手で操作する速さを基準線**に。速すぎ・遅すぎの**両方**を検査するよう変更 |

### 次の選択肢（8枚目の素材）

1. **102項目の手動テスト**を実施するか、自動テストで代替と判断するか
2. **Phase 3**（学習結果の出力・学習ログの活用）。※アカウント・サーバー・個人情報の同意設計が前提となり規模が上がる
3. **コンテンツの磨き込み**（ヒント文の粒度・エンディングの読み味）

### フォント

`Segoe UI` → `Hiragino Sans` → `Meiryo` → sans-serif（アプリと同じ指定）。

### レイアウト原則

- 1スライド1メッセージ。**タイトルがメッセージ**
- 本文は箇条書き3〜5行まで。**それ以上はノート欄へ**
- 数字は大きく見せる（3枚目・5枚目の主要指標）
- 図解優先：対比は2列、プロセスは矢印、分類は矩形
- **4枚目（主題）は「触っていない71本」を図で見せる**（既存＝変更なし／追加＝別ファイル、の2層構造）
- **6枚目は「自動が見る範囲」と「人が見る範囲」の対比2列**で組む
- 7枚目（限界・反省）は赤系を使うが**ネガティブに見せない**（何が起きたか→どう直したか→次にどうするか の3列）

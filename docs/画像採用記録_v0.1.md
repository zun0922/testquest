## 配信形式の変更：PNG → WebP 圧縮（2026-08-21・宿題B-6）

採用画像そのもの（構図・顔）は不変。**配信形式のみの決定的処理**であり、画像アセットルールの「①クロップ・合成（顔が変わらない）」と同列に扱った。

| 項目 | 内容 |
|------|------|
| 方式 | `sharp` で WebP 再エンコード（**quality 90・alphaQuality 100・effort 6**）。`scripts/compress-images.mjs` に恒久化 |
| 対象 | 採用済み実PNG 27枚（立ち絵5キャラ×5表情＝25＋背景 office/server） |
| 結果 | **38,485KB → 2,109KB（5.5%・約1/18）**。背景 office 4406→239KB・server 4025→184KB／立ち絵 tanaka 1491→75KB・mio 1396→58KB・takumi 731→49KB |
| 品質判断 | 顔の等倍クロップ比較（元／PNGパレット／WebP q90／q82）で目視。元画像の肌のディザ状ノイズが僅かに平滑化されるのみで、線・目・輪郭は保持。**`alphaQuality:100` により透過エッジは無劣化**（実画面で白フリンジなしを確認）。背景は目視差ほぼゼロ |
| 元PNGの保管 | `assets-candidates/original-png/`（27枚・37.58MB・gitignore対象）。再エンコード元として保持 |
| 組み込み | `assets.ts` EXT→`webp`（参照箇所は同ファイルのみ）。単体153件・E2E 15件 全PASS・実画面スクショで背景／立ち絵2体の描画とグレーアウト（UI-RULE-004）を確認 |
| 不採用案 | **pngquant / PNGパレット化**＝削減21%止まりで libimagequant が GPL-3.0（licensing-policy 抵触）。**PNGロスレス最適化**＝97%で無意味（既に最適化済み） |

- ライセンス：sharp=Apache-2.0／libwebp=BSD-3-Clause。プリビルドバイナリ `@img/sharp-win32-x64` は `Apache-2.0 AND LGPL-3.0-or-later`（libvips）だが **devDependency＝ビルド時ツールで配布物に含まれず、出力WebPは画像データのため伝播なし**（根拠は `LICENSES.md`）
- 費用：0円（生成API不使用）
- 注意：git 履歴の旧PNGは残るため `.git` 自体は縮まない。効果は配信量・チェックアウト量・今後の増加抑制

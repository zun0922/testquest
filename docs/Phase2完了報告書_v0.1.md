## 6. 人間による機能テストの実施状況

### 6.1 Phase 2 分（ST-M2）＝**実施済み**

PO が iPhone 実機・横持ち・本番URLで**7件すべてを実施**（リモートのため一問一答形式）。

**結果：PASS 7／要改善 2（対応後に再確認しPASS）／FAIL 0**

| 指摘 | 内容 | 対応 |
|------|------|------|
| スキップ速度 | 「速すぎる」→是正後「実感がない」 | **2度の是正**を経てPASS（140ms＋4ms/字＋モード表示＋停止理由） |
| 声と口調 | 「澪は丁寧語にしたい」 | **全144本を改稿**・音声再生成しPASS |

### 6.2 E2Eでは拾えなかった指摘

手動テストを**7件に絞った**判断が機能した。E2E は「進む・止まる」は検証できるが、
**速さが人間に合うか**・**声と口調が噛み合うか**は判定できない。この2件はいずれも実機でしか出てこなかった。

### 6.3 プレイ中に見つかった改善点3件（別枠）

ST-M2 とは別に、PO が**音声・口調以外**で気づいた点。すべて対応済み（2026-09-19 本番反映）。

1. **問題を読む時間が足りない** → 暗幕を本文にかけない構造へ＋設問の長さに応じた間（0.45〜1.6秒）
2. **中断・ログのアイコンが分からない** → 図柄を分けラベルを添えた
3. **ヒント文がアイコンの背面で欠ける** → ヒント文を左・選択肢を右の横並びへ

## 8. プロセスの実績と反省

### 8.1 うまくいったこと

| 実績 | 中身 |
|------|------|
| **PR運用の導入** | Phase 2 から PR 8件を運用。CI は**ブランチ push では走らず PR で起動**する仕様を把握して運用に組み込んだ |
| **段階実行の徹底** | 課金API（画像）は1枚→PO確認→バッチ。シナリオ改稿は第1章8本→承認→残り136本 |

| **機械で担保する習慣** | 「口調だけ変えた」を目視でなく**用語・数値・コード片の突き合わせ**で検証（不一致0件） |
| **本番スモークの定着** | 全8回のマージすべてで本番を実測確認 |

### 8.2 反省点

| 反省 | 内容 | 是正 |
|------|------|------|
| **受け入れ基準を後から作った** | 5機能が本番稼働してから AC-013〜017 を新設した | テスト計画書 §2.2 に教訓を恒久化。次フェーズは**実装前に AC を置く** |
| **文書が3週間取り残された** | テスト計画書は「未実装フェーズの機能」、テスト仕様書は「本書では扱わない」と**実態と正反対**の記述のままだった | 同上。**機能を本番へ出すときはテスト文書の対象範囲も同時に動かす** |
| **自分の修正が別の不具合を生んだ** | 「選択肢表示中にボタンが押せない」を直すためボタンを前面へ上げ、**ヒント文を隠した** | レイアウト変更は**実寸の重なり検証**をE2Eに入れる（実装済み） |
| **是正の振り戻しが過剰だった** | スキップ速度を90ms→580msにして「連打より遅い」状態を作った | **人が手で操作する速さが基準線**。E2Eは上下**両方**の幅で固定する |

## 1. 目的とスコープ

各キャラクターのセリフに音声を付け、ビジュアルノベルとしての没入感と「聞きながら学ぶ」体験を提供する。

| 項目 | 内容 |
|------|------|
| 対象 | **キャラクターのセリフのみ**（569ノード・24,731字。ナレーションを含む） |
| 対象外 | フィードバック解説（840件・123,888字）・選択肢テキスト・UIラベル |
| 着手範囲 | **FL第1章5本（39ノード・1,469字）でパイロット** → 品質・工数・容量を実測してから全展開 |
| 前提 | 音声は「あれば鳴る」機能。**無い・OFF・再生失敗のいずれでも従来どおりプレイできる**ことを実装で保証する |

## 2. 生成方式：VOICEVOX（CPU版）

無料であることに加え、本プロジェクトの原則と噛み合うため採用する。

| 理由 | 内容 |
|------|------|
| 決定的処理 | HTTP API で同一テキスト＋同一パラメータ→同一音声。開発フロー定義の「決定的処理＞生成的処理」に合致 |
| 読みの制御 | ユーザー辞書で専門用語の読みを恒久修正できる（学習教材では品質の生命線） |
| 再生成が自由 | 費用ゼロ。シナリオ改訂のたびに作り直す運用に耐える |
| CPUで足りる | GPU が要るのは音声モデルの**学習**時のみ。既成ライブラリの利用は CPU 推論で完結する |

- 導入：`winget install HiroshibaKazuyuki.VOICEVOX.CPU`（エンジンは既定で `http://127.0.0.1:50021`）
- 代替候補：**AivisSpeech**（Style-Bert-VITS2 系・より自然だがモデルごとに規約が異なる）。STEP 0 の試聴で比較する

## 5. 配信形式とファイル配置

| 項目 | 値 | 理由 |
|------|----|------|
| 形式 | **AAC（`.m4a`）48kbps モノラル** | **Ogg Opus は iOS 16 以前の Safari が再生できない**。要件7.2 の対応ブラウザに Safari が含まれるため、容量より確実性を取る |
| 配置 | `public/audio/{scenarioId}/{nodeId}.m4a` | 画像（`assets.ts`）と同じく**規約でパスが決まる**方式。**シナリオJSONは一切変更しない**（監修済み71本を不変に保つ） |
| 索引 | `public/audio/manifest.json` | 存在判定（404を出さない）・尺・テキストのSHA-256（差分再生成） |
| 原本 | `assets-candidates/voice-wav/`（gitignore） | 再エンコード用の wav を保管（画像の `original-png/` と同型） |

**容量（全71本・569ノードの実測／2026-08-30）**：**26.09MB**・合計 **4,226秒＝70.4分**（平均 7.4秒／47KB per ノード）。
参考：パイロット39ノード時点は 1.56MB・250.9秒。当初見積り（80〜100分・30MB）に対し **70.4分・26.1MB** で収まった。
ビルド成果物 `dist/audio` は 28MB。

## 6. 読み辞書

`scripts/voice-dict.json` が正。`node scripts/gen-voice-dict.mjs` で VOICEVOX のユーザー辞書へ登録する。

- **辞書をリポジトリで管理する**ことで、誰の環境で生成しても同じ読みになる
- 収録語は実際のセリフから抽出した英字略語・専門用語のみ（過剰登録はアクセントを不自然にするため避ける）
- 読み間違いを見つけたら辞書に追加 → `gen-voice.mjs --force` で鳴らし直す

> **既知の課題（STEP 3 でPO判断）**：AL-TTA には疑似コードをバッククォートで囲んだセリフが**5件**ある（`al-tta-2-01/q4`・`al-tta-2-02/intro-scene`・`al-tta-3-01/q4`・`al-tta-5-03/brief1`・`al-tta-5-03/q2`）。現状はバッククォートを除去して読ませるだけの最小正規化。コード自体をどう扱うか（読み替え・音声化除外）は全展開時に決める。

## 7. 制作フロー

| STEP | 内容 | 判断者 |
|------|------|--------|
| 0 | VOICEVOX導入 → `voice-audition.mjs --policies` で**規約を原文取得** → `voice-audition.mjs` で全話者の試聴サンプル生成 → 候補を絞って `--speakers` で役ごとの実セリフを生成 | PO（音源選定） |
| 1 | `gen-voice-dict.mjs` で辞書登録 → `gen-voice.mjs --scenario fl-1` でパイロット生成 | AI |
| 2 | **PO体感確認**（読み精度・演出・クリック挙動） | PO |
| 3 | 全71本展開（`gen-voice.mjs`）・辞書調整 | PO（品質判定） |

### 7.1 全量生成の運用（2026-08-30 の実績）

- **速度は約6〜7秒/ノード**（CPU推論）。569ノードで**実測 約50分**
- **章単位で分割して実行する**（`--scenario fl-3` など）。1回の実行が10分を超えると実行環境のタイムアウトに掛かるため
- **1シナリオ完了ごとに manifest を保存**するので、途中で止まっても次回はハッシュ一致でスキップされ**続きから再開**できる
- **メモリに注意**：物理7.7GBの環境で、エンジン常駐（約0.7GB）＋長時間実行により空きが0.4GBまで低下し、**`/synthesis` が HTTP 500 を返す／Node が Fatal OOM で落ちる**事象が発生した。**エンジンを再起動すると解消**する（再起動後は空き1.2GBに回復）
- 散発的な 5xx は `gen-voice.mjs` が**最大3回リトライ**する（接続不可と4xxは即座に失敗させる）

## 8. 権利・ライセンス（採用前に必須）

VOICEVOX 本体は無償・商用可だが、**音声ライブラリのキャラクターごとに規約が異なる**。画像で確立した権利チェックと同じ手順で確認し、判定根拠まで `docs/音声採用記録_v0.1.md` に残す。

**確認手段：** キャラクター個別の規約は VOICEVOX エンジンの `/speaker_info` API が一次情報として返す。
`node scripts/voice-audition.mjs --policies` で全話者分を `docs/音声ライブラリ規約一覧_v0.1.md` に機械的に書き出せる（伝聞ではなく原文で確認する）。

1. VOICEVOX 本体の利用規約（**版と確認日**を記録）
2. 採用音源ごとのキャラクター利用規約
   - 商用利用の可否（社内教材でも法人の営利活動に該当しうる）
   - **クレジット表記の正確な文言**（例：`VOICEVOX:○○`）
   - **別キャラクターへの声当ての可否**（TestQuest のオリジナルキャラに当てるため）
   - 禁止事項（イメージを損なう利用など）
3. クレジット表記の実装（タイトル画面の「非公式の学習教材」注記の隣に併記）

**実装方法**：`gen-voice.mjs` が **manifest に載っている＝実際に配信している音源だけ**を `credits` として書き出し、
`TitleScreen` がそれを表示する（フロント側に配役表を二重に持たない）。未使用の配役は表示されない。
表記は policy 原文が示す `VOICEVOX:{音源名}` 形式。**表示漏れは規約違反に直結するため E2E で担保している**。

## 9. 品質基準（試聴の観点）

| 観点 | 基準 |
|------|------|
| 読み | 専門用語・英字略語の読み間違いが無い（あれば辞書へ） |
| アクセント | 不自然な抑揚が無い |
| 話速 | 学習内容を聞き取れる速さ（速すぎない） |
| 音量 | 役ごとの音量差が大きくない |
| 一貫性 | 同じ役の声・話速がシナリオ間でぶれない |
| 演出 | テキスト送りと並行して鳴っても読みづらくない |

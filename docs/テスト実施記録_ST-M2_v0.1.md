## 3. 要改善課題

### 課題 #1：澪の口調を丁寧語にする（ST-M2-002-TC-002）

**現状**：本文は匠と共通（常体）のままで、差し替えているのは一人称・二人称・名乗りの**7か所のみ**。
波音リツの声で「〜だ」「〜する」と話すことになる。

**PO判断**：**丁寧語に変更する**（影響範囲を提示したうえでの決定）。

**対応済み（2026-09-13）**

| 項目 | 実績 |
|------|------|
| 起案 | **144本**（第1章8本で口調の基準を固めてPO承認 → 残り136本へ展開） |
| 本文差分 | **133件**（**11件は体言止めの設問で原文のまま**。同一の差分は持たない＝門番テストが検出） |
| 音声 | **144本・17.4分・6.4MB**（波音リツ・費用ゼロ） |
| シナリオJSON 71本 | **変更なし** |
| 監修資料 | `docs/澪版セリフ_監修資料_AL-TTA全章_v0.1.md`（**データから機械生成**＝転記ミスが混入しない） |

**学習内容が変わっていないことの機械的な担保**

匠版と澪版の双方から**専門用語・数値・コード片**（`if(x>0){A} else {B}` 等）を抽出して突き合わせ、
**不一致0件**を全144本で確認した。「口調だけを変える」という約束を、目視ではなく機械で担保している。
あわせて匠の職人気質の語彙（俺・お前・技術屋・職人・解析屋）の残存が**0件**であることも確認した。

**実プレイ確認の方法**

本番では `?unlockAll=1` が無効（dev限定でバンドルから除去済み）のため、モバイル単体では AL編に到達できない。
**確認専用ブランチ（`DO-NOT-MERGE/preview-unlock`・差分は1行）** を作ってプレビュー環境でのみ解放し、実機で確認した。
**本番のコードには一切手を入れていない**。確認完了後、ブランチは削除済み。

| 影響 | 規模 |
|------|------|
| 本文差分 | **7か所 → 144か所**（匠のセリフ全件） |
| 音声の再生成 | **144本**（約16分・費用ゼロ） |
| 監修 | 144本分のレビューが必要 |
| シナリオJSON 71本 | **変更不要**（差分は `casting.json` に持つ設計のまま） |

> 設計上は「差分が7か所で済む」ことを限定実装の根拠にしていたが、**実機で聴くと口調の問題は声とセットで立ち上がる**。
> 文字だけのレビューでは判断できなかった観点であり、手動テストで拾えた価値がここにある。

### 課題 #2：既読スキップが速すぎる（ST-M2-005-TC-001）

**現状**：既読ノードを 90ms 間隔で自動送りする（約11ノード/秒）。

**所見**：仕様上の狙い（「何が流れたか目で追える」）を**実機では満たしていない**。
E2E は「進む・止まる」は検証できるが、**速さが人間にとって適切か**は判定できない。

**対応方針**：送り間隔を**本文の長さに応じて変える**（短い行は速く、長い行は長めに留まる）。
固定値を大きくするだけだと、短い相槌のような行で無駄に待たされる。

**対応済み（2026-09-13）**

| 項目 | 内容 |
|------|------|
| 送り間隔 | 一律 90ms → **260ms ＋ 8ms/字（上限1000ms）**。実データの中央値40字で約580ms・最長196字でも1000ms |
| **スキップ中の音声** | **鳴らさないようにした**。従来は1秒に約11回、声が鳴っては切られる状態だった（今回の実機確認で気づいた副次的な問題） |
| 根拠の記録 | `src/utils/skip.ts` に実測値（569ノード・中央値40字・最長196字）と判断理由を記載 |
| 検証 | 単体7件（`skip.test.ts`）＋E2E2件を追加 |

**再確認で判明（同日・2回目の是正）**

PO実機確認：「アイコンを押しても速くなっているのか実感がない。押している間だけ速くなる仕様？」

| 分かったこと | 内容 |
|-------------|------|
| **遅くしすぎた** | 約580ms/ノードは**人が連打する速さ（200〜330ms）より遅い**。早送りとして意味をなしていなかった |
| **モードだと伝わらない** | 仕様はもともとON/OFFのトグルだが、**右上のボタンの色しか手がかりが無く**、本文を見る視線に入らない |
| **押しても無反応に見える** | 未読に当たると自動解除されるため、**何も起きなかったように見える**ことがある |

**2回目の是正（2026-09-13）**

| 項目 | 内容 |
|------|------|
| 送り間隔 | 260ms＋8ms/字 → **140ms＋4ms/字（上限500ms）**。中央値40字で**約300ms**＝連打よりはっきり速く、目では追える |
| **モード表示** | 本文の真上に「**⏩ スキップ中（画面をタップで停止）**」を常時表示 |
| **停止理由の表示** | 自動で止まったとき「**選択肢のため**」「**ここから未読のため**」を2.6秒表示。自分で止めたときは出さない |
| 検証 | 単体**8件**＋E2E**5件**（速度は上下の幅で検証＝速すぎ・遅すぎの両方を固定。モード表示・停止理由・未読時・手動停止時の非表示） |

> **教訓**：速度の調整は「遅くすれば直る」ではない。**人が手で操作する速さが基準線**であり、それより遅い自動送りは機能として成立しない。
> また、モードの有無は**操作している場所（本文）で示す**必要がある。画面隅のボタンの状態表示だけでは伝わらない。

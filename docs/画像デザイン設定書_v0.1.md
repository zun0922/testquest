## 1. 目的

現在の暫定SVGアセット（`scripts/gen-assets.mjs` 生成）を、画像生成AIによる本格アート（PNG）へ差し替える。
本書は生成に先立ち、以下を確定させる：

1. 全キャラ共通のアートスタイル（一貫した世界観・既存作品類似リスクの回避）
2. 各キャラクターの外見仕様（表情差分で「別人化」しないための固定情報）
3. 技術要件（サイズ・形式・命名・組み込み手順）
4. 生成・採用・権利確認のワークフロー

**本書の承認（STEP 3）なしに画像生成は開始しない。**

## 2. 共通スタイル定義

| 項目 | 指定 |
|------|------|
| スタイル | 日本のアニメ調イラスト（セルシェーディング・クリーンな線画） |
| 陰影 | フラット寄り・1〜2段影（表情差分生成時の一貫性を保ちやすくするため） |
| 色調 | 明るく清潔感のあるパステル〜中彩度。ゲームUI（ダークネイビー基調）に映える配色 |
| 構図 | 立ち絵はバストアップ（胸から上）・正面〜やや斜め・視線は正面 |
| 衣装 | オフィスカジュアル（企画書§6.4。スーツほど堅くなく、ITエンジニアらしさ） |
| 禁止事項 | **特定の既存作品名・作家名・キャラクター名をプロンプトに含めない**（§15 類似性リスク対策） |

## 3. 技術要件

> **サイズの根拠について**：設計書 v1.1 §2 が規定するのは命名と「PNG・透過背景」のみで、解像度の規定はない。
> 本節のサイズは**表示実装**（`ScenarioPlayer.tsx`：立ち絵 `h-[58vh] w-auto`・背景はフルビューポート `bg-cover`）から逆算して定めた。

### 3.1 立ち絵

| 項目 | 指定 |
|------|------|
| 形式 | PNG・**背景透過**（透過出力不可のAIの場合は単色背景で生成し後処理で切り抜き） |
| 表示実装 | 高さ58vhに拡縮・幅は自動（`object-contain`）。**表示品質は縦解像度で決まる** |
| サイズ | 縦 **1600px以上** を推奨（フルHD画面の58vh≒630pxの約2.5倍＝高DPI対応）。縦横比は縦長 約3:4 を目安（現行SVG 220×300 と同比率で画面バランス維持） |
| 余白 | **上下の透明余白を最小にする**（頭頂〜胸下がフレームいっぱい）。余白が大きいと現行SVGより立ち絵が小さく表示される |
| 範囲 | バストアップ。頭頂が切れないこと。左右に手・小物がはみ出さないこと |
| 表情 | 5種：`normal`（穏やかな真顔）/ `happy`（笑顔）/ `angry`（眉を寄せる）/ `sad`（悲しげ）/ `thinking`（考え込む・視線を外す） |
| 一貫性 | 同一キャラの5表情で髪型・髪色・服・輪郭・画風が変わらないこと（採用判断の必須条件） |
| 配置先 | `public/images/characters/{id}/{expression}.png` |

### 3.2 背景

| 項目 | 指定 |
|------|------|
| 形式 | PNG（またはJPG。透過不要） |
| 表示実装 | 画面全体に `bg-cover bg-center`。**PC全画面では画面解像度まで拡大**され、**モバイル縦では中央約1/3幅のみ表示**（左右はクロップ） |
| サイズ | **1920×1080 以上（16:9）**。生成AIが対応するならより大きく（2560×1440等）してよい |
| 構図（セーフエリア） | **主要モチーフは中央1/3の縦帯に収める**（モバイルで左右が切られる前提）。窓・モニター等は左右に配置してよいが、切れて不自然にならないこと |
| 配置先 | `public/images/backgrounds/office.png` |
| 制約 | 中央〜下部に立ち絵とテキストウィンドウが重なるため、**主張の強いオブジェクトや文字を置かない**。彩度・コントラストは立ち絵より控えめにする |

### 3.3 組み込み

- 全PNG配置後、`src/utils/assets.ts` の `EXT` を `'svg'` → `'png'` に変更（1行）
- 差し替え後、E2E（walkthrough）と目視で表示確認（STEP 6）

## 6. 生成・採用ワークフロー

開発フロー v10.1 の構造をアート制作に適用する。

```
STEP A　基準画像生成（AI）　：normal 表情を各キャラ数案生成
STEP B　採用判断（PO）　　　：キャラごとに1案採用。不採用は理由を記録し再生成
STEP C　表情差分生成（AI）　：採用画像を基準に、編集機能で4表情を派生生成
STEP D　一貫性確認（PO）　　：5表情を並べて「同一人物か」を確認
STEP E　権利確認（人間）　　：§7 のチェックを実施し記録
STEP F　組み込み・確認　　　：PNG配置 → assets.ts 切替 → E2E＋目視（STEP 6相当）
```

- 使用サービスは **Gemini API（`gemini-3.1-flash-image`・課金必須）による画像編集方式** とする ※v1.2確定。経緯：無課金経路（Pollinations seed固定方式・kontext・表情シート・Stable Horde img2img）は目の対称性/スケール一貫性の品質基準に達せずPO判断で課金APIへ移行（費用は1枚≈6円）
- 表情差分は**採用済み基準画像を入力にした編集**で作る（プロンプト集v1.2 §3のガード文＝目の対称性維持を含む、を必ず使用）。テキストのみからの再生成は禁止
- 新キャラの基準画像（デザイン探索）は Pollinations.ai（無料）で行ってよいが、**採用画像は最終的にGemini編集で再作成し生成元を統一**する（系譜は採用記録に記録）
- 生成パラメータとプロンプトは `画像採用記録_v0.1.md` に記録し、再現可能性を保証する ※v1.1追加

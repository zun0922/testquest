## FR-009　シナリオデータロード

リスクベース重点（データ品質の門番）。設計書§3.4 の検証12項目を扱う。

### 本節のテスト方式（前提）

- **FT-009-001（検証12項目＋境界＋正常）：** 純ロジックのため **validator 単体テスト（Vitest）** で担保する（テスト仕様書 §8 主担当＝単体・計画書§10.3）。不正データは単体テストのフィクスチャ（テストコード内）または TD-SCN ファイルで与える。担当＝AI（コマンド実行）。
- **FT-009-002（ロード失敗回復）・FT-009-003（保守性）：** 実アプリの挙動確認のため **`VITE_SCENARIOS_PATH` でテストデータに切替**（設計書§10.4・本体§1.6 で選定）。担当＝人間／AI。

#### テストデータ切替の共通手順（FT-009-002・003 で使用）

設計書§10.4 のテスト用フックを使う。**本番データ（`public/data/scenarios/`）を一切変更しない。**

1. AI が対象ケースのデータを `public/data/scenarios_test/<ケース名>/` に準備する（`index.json` ＋ シナリオJSON。`<ケース名>` は TD-ID 等で命名）
2. ターミナルで環境変数を付けて起動する

```
VITE_SCENARIOS_PATH=/data/scenarios_test/<ケース名> npm run dev
```

Windows（PowerShell）の場合：
```
$env:VITE_SCENARIOS_PATH="/data/scenarios_test/<ケース名>"; npm run dev
```

3. テストを実施する
4. **後処理**：`Ctrl+C` で停止 → 環境変数なしで `npm run dev` を再起動し、本番データ（`/data/scenarios`）で正常起動することを確認 → テストログCSV `notes` に「<ケース名>使用・復元完了」を記録

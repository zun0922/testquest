## 1. 文書概要

### 1.1 目的

本書は、JSTQBシラバスベースのテストエンジニア育成ゲーム「TestQuest」の Phase 1（MVP）で実装する機能要件・非機能要件・受け入れ基準を定義する。設計者・実装者・テスト設計者が判断に迷わないことを目的とする。

### 1.2 適用範囲

- **詳細定義の対象**：Phase 1（MVP）＝シナリオ再生エンジン＋収録シナリオ（6.2）＋基本UI

- 画面の見た目（レイアウト・配色・装飾）は本書の対象外とし、別途作成するデザインモック（人間承認）で確定する。本書は機能・挙動・データのみを定義する

## 2. プロジェクト概要

### 2.1 背景と課題

テスト工学の教育コンテンツは座学・テキスト中心で学習継続率が低く、研修と現場の乖離も大きい（詳細は企画書2章）。

### 2.2 目的

- JSTQBシラバスの知識を、シナリオ選択型ゲーム体験として楽しく定着させる
- FL→ALの段階学習と採用導線（プレイ結果提出）を将来フェーズで提供する

### 2.3 プロジェクト情報

| 項目 | 内容 |
|------|------|
| プラットフォーム | Webアプリ（ブラウザで動作・PC/スマートフォン両対応） |
| 開発体制 | 1名（Claude Code によるAI支援開発）＋JSTQB有資格者の監修 |
| Phase 1 スコープ（実績） | シナリオ再生エンジン・シナリオ71本（FL27／AL-TM23／AL-TTA21）・5キャラクター・進捗のローカル保存 |
| Phase 1 スコープ（当初計画） | シナリオ再生エンジン・FL第1章5シナリオ・3キャラクター・進捗のローカル保存 |

## 3. 用語定義

| 用語 | 定義 |
|------|------|
| レベル | JSTQBの資格区分（FL / AL-TM / AL-TTA）。ゲーム内の大分類 |
| 章 | シラバスの章に対応するシナリオのグループ（例：FL第1章 テストの基礎） |
| シナリオ | 1話完結の学習単位。3〜5回の選択を含む。章に複数本属する |
| シーン | シナリオ内の1画面分の表示単位（背景・立ち絵・テキストの組）。データ上はノードと呼ぶ |
| 選択肢 | シーンでプレイヤーに提示される行動の候補（**原則3択**。2026-07-11 のかく乱肢改訂で全280問を3択に統一） |
| フィードバック | 選択直後に表示される解説（評価・理由・参照シラバス項番） |
| ステータス | プレイヤーの成長値4種（知識・スキル・自信・チームワーク） |
| 進捗 | シナリオのクリア状況・ステータス値・設定の総称。保存対象 |
| 編成パターン | 登場キャラクターの組み合わせ（A〜D）。Phase 2で実装。MVPは固定編成 |
| クリア | シナリオの最終シーンに到達した状態 |
| 機能テスト | 機能単位で人間が行う動作確認（受け入れテスト・UATとは呼ばない） |

## 5. 機能要件（Phase 1 MVP）

### 共通UIルール

全機能に適用する横断的仕様。個別FRはここを参照し、重複定義しない。

| ID | ルール |
|----|--------|
| UI-RULE-001 | 操作不可の要素（未実装機能・未解放コンテンツ・セーブなし時の「つづきから」等）はグレーアウト表示し、タップ・クリックに反応しない。ツールチップ等の理由表示は不要 |
| UI-RULE-002 | シーンテキストは1ページ＝最大200文字とし、表示領域内に収める。200文字を超える会話はシナリオデータ側で複数シーンに分割する（実行時の自動折り返し送りは実装しない） |
| UI-RULE-003 | 選択肢の表示順はシナリオデータの定義順とする。シャッフルしない |
| UI-RULE-004 | 立ち絵は発話中のキャラクターを通常表示、その他のキャラクターをグレーアウト表示する。同時表示は最大2体 |
| UI-RULE-005 | 画面操作の主導線はクリック／タップのみで完結させる（キーボード入力を必須としない） |
| UI-RULE-006 | ステータスの内部値（0〜100）・変動値（+1〜+5）は画面に数値・パーセントで表示しない。表示はメーター・色等の抽象表現とする（具体表現はデザインモックで確定）。目的：数値の最大化を狙う攻略的プレイを防ぎ、判断そのものを考えさせる。没入感の維持。数値の開示はプレイ結果送信（FR-P4-002）でのみ行う |

### FR-001　タイトル画面

| 項目 | 内容 |
|------|------|
| 要件ID | FR-001 |
| 機能名 | タイトル画面 |
| 優先度 | 必須（Must） |
| 目的 | ゲームの開始・再開の入口を提供する |
| 概要 | タイトルと「はじめから」「つづきから」を表示する |

**詳細仕様**

- 「はじめから」選択時：確認ダイアログなしで新規進捗を作成し、章・シナリオ選択画面（FR-002）へ遷移する。既存の進捗が存在する場合は「進捗が削除されます」の確認ダイアログを表示し、OKで上書き・キャンセルでタイトルに留まる
- 「つづきから」選択時：保存済み進捗を読み込み、章・シナリオ選択画面へ遷移する
- 保存済み進捗が存在しない場合、「つづきから」は UI-RULE-001 に従い非活性とする
- プレイヤー名の入力は行わない（主人公は二人称「あなた」で表現し、個人情報を取得しない）

### FR-002　章・シナリオ選択

| 項目 | 内容 |
|------|------|
| 要件ID | FR-002 |
| 機能名 | 章・シナリオ選択 |
| 優先度 | 必須（Must） |
| 目的 | 学習単位（シナリオ）の選択とクリア状況の確認手段を提供する |
| 概要 | レベル・章ごとのシナリオ一覧をクリア状況付きで表示し、選択でシナリオを開始する |

**詳細仕様**

- 表示はレベル→章の2階層とする。シナリオインデックスに登録のある章を活性、登録のない章は UI-RULE-001 に従い非活性とする（「制作中」の旨をラベル表示）
- AL（AL-TM／AL-TTA）は FL 全章クリアで解放する（企画書5.5）。未解放時は解放条件をラベル表示する
- シナリオ一覧はインデックスの登録内容を レベル→章→シナリオデータの `order` 昇順で表示する
- 各シナリオに以下を表示する：タイトル・クリア状況（未プレイ／クリア済み）・所要時間目安
- シナリオはどの順番でも選択可能とする（章内の順序制限は設けない）
- クリア済みシナリオは再プレイ可能とする。再プレイ時のステータス変動は加算しない（クリア済みシナリオの再プレイは学習用であり、ステータスは初回クリア時の変動のみ有効）
- 現在のステータス4種をメーター表示で画面内に常時表示する（UI-RULE-006。数値は表示しない）

### FR-003　シナリオ再生

| 項目 | 内容 |
|------|------|
| 要件ID | FR-003 |
| 機能名 | シナリオ再生（シーン進行） |
| 優先度 | 必須（Must） |
| 目的 | ビジュアルノベル形式の学習体験の中核を提供する |
| 概要 | シーンを順に表示し、クリック／タップで次のシーンへ進行する |

**詳細仕様**

- 1シーンには以下を表示する：背景・キャラクター立ち絵（0〜2体・UI-RULE-004）・話者名・本文テキスト（UI-RULE-002）
- 画面の任意位置のクリック／タップで次のシーンへ進む（選択肢シーンを除く）
- テキストは1文字ずつの送り表示とし、表示中のクリックで全文を即時表示する（2回目のクリックで次シーンへ）
- シナリオ中断機能を設ける：メニューから「シナリオを中断」を選ぶと確認ダイアログの後、章・シナリオ選択画面へ戻る。中断したシナリオの途中状態は保存しない（再選択時は最初から）
- 既読スキップ・オート再生・バックログはMVPでは実装しない（Phase 2以降の検討事項）

### FR-004　選択肢と分岐

| 項目 | 内容 |
|------|------|
| 要件ID | FR-004 |
| 機能名 | 選択肢と分岐 |
| 優先度 | 必須（Must） |
| 目的 | JSTQB知識を問う判断体験を提供する（ゲームループの中核） |
| 概要 | 選択肢シーンで2〜3択を提示し、選択に応じてステータス変動・フィードバック・分岐を行う |

**詳細仕様**

- 選択肢シーンでは本文テキストと選択肢（2〜3個・UI-RULE-003）を表示し、選択するまで進行しない
- 選択肢に制限時間は設けない
- 選択すると以下を順に実行する：(1) ステータス変動の適用（FR-006）、(2) フィードバック表示（FR-005）、(3) シナリオデータで指定された次シーンへの分岐
- 1シナリオに選択肢シーンは3〜5回含まれる（コンテンツ要件 6.1）
- 選択した選択肢は当該プレイ中のみ記録し、フィードバック表示に使用する（選択履歴の永続保存は Phase 4）

### FR-005　フィードバック表示

| 項目 | 内容 |
|------|------|
| 要件ID | FR-005 |
| 機能名 | フィードバック表示 |
| 優先度 | 必須（Must） |
| 目的 | 「なぜその判断が良い／良くないか」を理解させ、学習効果を生む |
| 概要 | 選択直後に固定フィードバックテキストを表示する |

**詳細仕様**

- フィードバックには以下を含める：(1) 選択の評価（3段階：最適／可／要改善）、(2) 理由の解説（最大400文字）、(3) 参照シラバス項番（例：FL 1.2.1）
- 評価3段階の表示色：最適＝緑系、可＝黄系、要改善＝赤系（具体色はデザインモックで確定）
- フィードバックは「閉じる」操作（ボタン）で明示的に閉じ、次のシーンへ進む
- どの選択肢にも必ずフィードバックを定義する（「不正解だから解説なし」は許容しない）
- フィードバック文はAI生成＋監修者承認済みの固定テキストとする（動的生成は Phase 4）

### FR-006　ステータスシステム

| 項目 | 内容 |
|------|------|
| 要件ID | FR-006 |
| 機能名 | ステータスシステム |
| 優先度 | 必須（Must） |
| 目的 | 成長の可視化により学習継続の動機を生む |
| 概要 | 4ステータスを内部数値で管理・加算し、成長をメーター等の抽象表現で表示する |

**詳細仕様**

- ステータスは4種：知識・スキル・自信・チームワーク。範囲は0〜100の整数、初期値は各10
- 選択肢ごとに1つ以上のステータスへ +1〜+5 の変動をシナリオデータで定義する。MVPでは減算（マイナス変動）は使用しない（不正解でも学びがある設計のため。企画書7.1）
- 上限100を超える加算は100で打ち切る（クランプ）
- 内部値・変動値は画面に数値表示しない（UI-RULE-006）。メーターの表示量は内部値に比例させる
- 変動時は対象ステータスが成長したことを示す表示（メーターの伸び・アイコンの強調等）をフィードバック（FR-005）内に含める。増分の数値は表示しない
- シナリオクリア時（FR-007）に当該シナリオでの成長をメーターの変化（プレイ前→プレイ後）として表示する
- 再プレイ時の扱いは FR-002 の仕様に従う（加算しない）

### FR-007　シナリオ結果表示

| 項目 | 内容 |
|------|------|
| 要件ID | FR-007 |
| 機能名 | シナリオ結果表示 |
| 優先度 | 必須（Must） |
| 目的 | 1シナリオの学習成果を要約し、達成感と振り返りを提供する |
| 概要 | 最終シーン到達時に結果画面を表示し、クリアを記録する |

**詳細仕様**

- 結果画面には以下を表示する：シナリオタイトル・選択回数と評価内訳（最適／可／要改善の個数）・ステータスの成長（プレイ前→プレイ後のメーター比較・UI-RULE-006）・参照したシラバス項番の一覧
- 結果画面の「章選択へ戻る」ボタンで章・シナリオ選択画面（FR-002）へ遷移する
- 結果画面表示時点でクリア状況・ステータスを進捗として保存する（FR-008）
- エンディング判定（ステータス分布によるFL編エンディング）は Phase 2 で実装する

### FR-008　進捗保存

| 項目 | 内容 |
|------|------|
| 要件ID | FR-008 |
| 機能名 | 進捗保存（ローカル） |
| 優先度 | 必須（Must） |
| 目的 | 中断・再開可能にし、すきま時間での継続学習を支える |
| 概要 | 進捗をブラウザの localStorage に保存・復元する |

**詳細仕様**

- 保存対象：シナリオごとのクリア状況・ステータス4種の現在値・初回クリア時の評価内訳
- 保存タイミング：シナリオ結果表示時（FR-007）。シナリオ途中のオートセーブは行わない
- localStorage が使用不可の環境（プライベートブラウズ等）では、タイトル画面に「この環境では進捗が保存されません」と表示し、プレイ自体は可能とする
- 保存データに個人情報・端末識別子を含めない
- 進捗の削除は FR-001「はじめから」の上書き確認による（独立した削除メニューはMVPでは設けない）
- 保存データのスキーマにバージョン番号を含め、将来の形式変更時に移行処理を可能にする

### FR-009　シナリオデータロード

| 項目 | 内容 |
|------|------|
| 要件ID | FR-009 |
| 機能名 | シナリオデータロード |
| 優先度 | 必須（Must） |
| 目的 | コンテンツをコードから分離し、追加・改訂を容易にする（シラバス改訂対応） |
| 概要 | JSONのシナリオデータを読み込み、スキーマ検証する |

**詳細仕様**

- シナリオデータは1シナリオ＝1JSONファイルとし、静的ファイルとして配信する
- アプリ起動時に章・シナリオの一覧（インデックスJSON）を、シナリオ開始時に当該シナリオJSONをロードする
- ロード時にスキーマ検証を行う：必須フィールド欠損・参照先ノード不在・選択肢数が2〜3の範囲外・テキスト長超過（6.1）を検出した場合、当該シナリオを開始せずエラー画面を表示する
- ロード失敗（ネットワークエラー・検証エラー）時：エラーメッセージと「再読み込み」ボタンを表示する。進捗（FR-008）は破壊しない
- エラーメッセージには技術詳細（スタックトレース等）を表示しない

## 6. コンテンツ要件

### 6.1 シナリオデータ仕様

| 項目 | 制約 |
|------|------|
| シナリオID | `fl-1-01` 形式（レベル-章-連番）。一意 |

## 7. 非機能要件

### 7.1 パフォーマンス

| 項目 | 基準 | 計測条件 |
|------|------|----------|
| 初期表示（タイトル画面） | 3秒以内 | 一般的な家庭用回線・キャッシュなし |
| シーン遷移 | 0.5秒以内 | クリックから次シーン表示まで |
| シナリオJSONロード | 2秒以内 | シナリオ選択からシナリオ開始まで |

### 7.2 ユーザビリティ

- PC（横画面）・スマートフォン（**横持ち**）でプレイ可能なレスポンシブ対応とする（ペルソナA「通勤中にスマホで」に対応）
- スマートフォンの**縦持ち**（`orientation: portrait` かつ幅 820px 以下）では、回転案内オーバーレイを全画面表示して操作を遮る（AC-011）。立ち絵の表示高（68vh）が縦持ちでは画面幅を超えレイアウトが破綻するため（2026-07-04 実機確認でPO指摘 → 設計書 v1.3 で決定）
- 対応ブラウザ：Chrome・Edge・Safari の最新版
- 文字サイズは スマートフォン実機で読める大きさを確保する（具体値はデザインモックで確定）

### 7.3 セキュリティ・プライバシー

- 個人情報を取得・保存・送信しない（FR-001・FR-008）
- 外部へのデータ送信は行わない（アクセス解析の導入はPOの承認を得てから）
- シナリオテキスト表示時のXSS対策（エスケープ処理）を実装する
- `npm audit` の高・中リスク0件を維持する

### 7.4 保守性・拡張性

- シナリオの追加・修正がコード変更なしで完結すること（JSONの追加・差し替えのみ）
- シナリオデータに参照シラバス項番を保持し、シラバス改訂時に影響シナリオを機械的に特定できること
- 進捗データのスキーマバージョン管理（FR-008）により将来の形式変更に対応できること
- Phase 2以降の機能（エンディング判定・編成パターン・AL解放）を見据え、レベル・章・編成をデータ構造上拡張可能にしておくこと（実装は不要）

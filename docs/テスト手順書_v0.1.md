## 1. 本文書の読み方

### 1.1 手順書の構造

各テストケースは以下の形式で記述する。全セクションが必須。

```
### [TC-ID]
- 観点ID：[観点ID]
- 対応要件：[FR-XXX / AC-XXX / NFR-XXX]
- テストデータ：[TD-XXX参照 または「なし」]
- 担当：[人間 / AI（コマンド実行）/ AI（コードレビュー）]

**事前条件**
1. [具体的な状態]

**手順**
1. [1操作1行]

**確認**
1. [確認内容] → 期待値：[具体的な値・状態]

**後処理**
1. [復元・ログ記録等]／なければ「なし」

**合否判定**
- PASS：全確認項目が期待値通り
- FAIL：1つでも期待値と異なる
```

### 1.2 DevTools の開き方

- **Chrome / Edge**：F12 キー または 右クリック→「検証」
- **Safari**：環境設定→詳細→「メニューバーに開発メニューを表示」をON後、「開発」→「Webインスペクタを表示」

### 1.3 内部ステータス値の確認方法（localStorage 直読・AC-006）

ステータスの数値は画面に出ない（UI-RULE-006）。内部値の正しさは localStorage を直読して確認する。

1. DevTools を開き **Console** タブを選択する
2. 以下を入力して Enter を押す

```javascript
JSON.parse(localStorage.getItem('testquest:save'))
```

3. 展開された保存データの `status`（`knowledge` / `skill` / `confidence` / `teamwork`）と `cleared` を読む
   - 新規開始直後は各ステータスが `10`（`INITIAL_STATUS`・設計書§5）

> キー名 `testquest:save` は設計書§5・§10.3 準拠。値は 0〜100 で内部管理される（クランプ）。

### 1.4 数値非表示の確認方法（背理法・UI-RULE-006・最重要）

「数値が出ないこと」を背理法で確認する。**ステータス領域に数字・% が1つでも観測されたら FAIL**。

1. 対象画面（`screen-play` / `screen-select` / `screen-result`）を表示する
2. DevTools の **Console** タブで以下を実行し、ステータス領域のテキストに数字・% が無いことを確認する

```javascript
// status-bar-* 要素のテキストに数字・%（半角/全角）が含まれないことを確認
Array.from(document.querySelectorAll('[data-testid^="status-bar-"]'))
  .map(el => el.textContent)
  .filter(t => /\d+\s*[%％]?/.test(t))
```

3. 返り値が **空配列 `[]`** であれば「数値非表示」が成立（マッチ0件）

> 正規表現 `/\d+\s*[%％]?/`（**半角・全角％の両方を含む**）は設計書§10.3・テスト仕様書 §4 FT-006-004 準拠。`status-bar-{key}` は `aria-valuenow` を付与しない設計（設計書§10.2）。

### 1.5 テキスト送りのスキップ（E2E・効率化）

テキスト送り（30ms/文字）を待たずに確認したい場合、URL に `?skipTyping=1` を付けて即時表示にできる（設計書§10・E2E専用フック・本番UIに影響しない）。例：`http://localhost:5173/?skipTyping=1`

### 1.6 テストデータの取り扱い

テストデータ（TD-SCN-XXX 等）は実施前に AI が準備し、実施後に必ず後処理（復元）を行い、テストログCSV `notes` 欄に記録する（`.claude/rules/common/testing/test-data-governance.md` 準拠）。本番シナリオ（`public/data/scenarios/`）と分離データ（`public/data/scenarios_test/`）を混在させない。

> **【決定済み】異常系シナリオの切替方式 ＝ (い) パス上書きenv `VITE_SCENARIOS_PATH`**（PO選定 2026-06-25・設計書 v1.1 §10.4 で定義）
> `scenarioLoader` は `import.meta.env.VITE_SCENARIOS_PATH ?? '/data/scenarios'` をベースパスに `index.json`／シナリオJSONを fetch する。環境変数未設定時は本番データを指し、本番挙動に影響しない。テスト時は `VITE_SCENARIOS_PATH=/data/scenarios_test/<ケース> npm run dev` で分離データに切替、テスト後は環境変数なしで再起動して本番復帰する。
> → FR-009 の手順は別ファイル `テスト手順書_v0.1_FR009.md` に展開済み（本フックを前提）。

> **【実データ準備 完了】TD群は生成済み（2026-08-21・宿題B-3）**
> 15ケース＝`public/data/scenarios_test/<ケース>/`（TD-SCN-001〜012〔003・005 は a/b の2パターン〕＋TD-SEC）。
> 生成は `node scripts/gen-testdata.mjs`（**手編集せずスクリプトを直して再生成する**）。各ケースの期待挙動は
> `src/utils/testdata.test.ts` が機械検証している（24件）。ケース一覧・TD-SAVE の投入文字列・TD-STORAGE の
> 再現方法は `public/data/scenarios_test/README.md` を参照。
>
> ⚠ **Windows の切替コマンドに注意（2026-08-21 実測）**
> **Git Bash では `VITE_SCENARIOS_PATH=/data/scenarios_test/<ケース>` が Windows パスへ自動変換され機能しない**
> （`C:/Program Files/Git/data/scenarios_test/...` に化ける＝MSYS2 のパス変換）。次のいずれかを使う。
>
> ```powershell
> # PowerShell（推奨）
> $env:VITE_SCENARIOS_PATH='/data/scenarios_test/td-scn-001'; npm run dev
> # 復帰
> Remove-Item Env:VITE_SCENARIOS_PATH; npm run dev
> ```
>
> ```bash
> # Git Bash を使う場合は変換を抑止する
> MSYS_NO_PATHCONV=1 VITE_SCENARIOS_PATH=/data/scenarios_test/td-scn-001 npm run dev
> ```
>
> 切替後は `http://localhost:5173/src/utils/scenarioLoader.ts` を開き、埋め込まれた値が
> `"/data/scenarios_test/<ケース>"` になっていることを確認してからテストを開始する（変換事故の検知）。

- **観点ID**：FT-006-004
- **対応要件**：FR-006 / AC-006 / UI-RULE-006
- **テストデータ**：なし
- **担当**：人間 / AI（E2E）

**事前条件**
1. シナリオ再生中（`screen-play` が表示されている）であること
2. ステータスメーター（`status-bar-*`）が画面に表示されていること

**手順**
1. `screen-play` を表示した状態にする
2. DevTools の Console で §1.4 のコマンドを実行する

**確認**
1. コマンドの返り値 → 期待値：空配列 `[]`（`status-bar-*` 配下に数字・%が0件）

**後処理**
なし

**合否判定**
- PASS：返り値が `[]`
- FAIL：1件でも要素が返る（数字・%が観測される）
